Balance Factor Analysis

The Balance Factor (BF) of a node is the height of its left subtree minus the height of its right subtree:
BF = height(left) - height(right)

🔍 Search
Binary path traversal to find value
Average Case O(log n)
Worst Case O(n)
Space O(h)
Average O(log n) for balanced trees. Worst O(n) when the tree degenerates into a linked list (completely skewed). Every node must be visited in the worst case.
➕ Insert
Find position + link new node
Average Case O(log n)
Worst Case O(n)
Space O(h)
Must traverse from root to correct position. Same traversal cost as search. Node creation itself is O(1) — only the traversal is O(h).
➖ Delete
Find + remove + restructure
Average Case O(log n)
Worst Case O(n)
Space O(h)
Case 3 (two children) requires finding inorder successor — an extra O(h) traversal. But this is still bounded by O(h) overall.
🔄 Traversal
Inorder / Preorder / Postorder
Time O(n)
Worst Case O(n)
Space O(h)
Always O(n) — every node visited exactly once. Space O(h) for recursion stack. For balanced trees h = O(log n), for skewed trees h = O(n).
⚠️ Why Worst Case is O(n)
When BST degenerates into a linked list

Inserting values in sorted order (e.g., 10, 20, 30, 40, 50) creates a right-skewed tree where every node has only a right child. This is the worst case for a BST — it behaves identically to a singly linked list.

To search for 50 in a 5-node right-skewed tree, you must visit all 5 nodes: 10 → 20 → 30 → 40 → 50

This is why self-balancing trees (AVL Trees, Red-Black Trees) were invented — they maintain O(log n) height automatically through rotations.

Height = n-1 = 4 (for 5 nodes)
